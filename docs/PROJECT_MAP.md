# Карта файлів проєкту

## GitHub і файли на комп’ютері

GitHub не є автоматичною копією комп’ютера. Він показує файли, які додали до Git і відправили в репозиторій. Сайт за посиланням README публікується саме з цього репозиторію.

Публічний репозиторій містить сайт, тренажери, їхні перевірки та правила продукту. Особисті відповіді, журнал навчання й робочі чернетки не мають потрапляти сюди автоматично. Локальна папка авторської системи зараз не є Git-копією цього репозиторію, тому її зміни самі на GitHub не з’являються.

Загальні правила дизайну та логіка вправ у цьому репозиторії є читабельними правилами продукту. Після їх зміни треба окремо оновити сайт, перевірити його й відправити зміни в GitHub.

## Де що змінюється

| Потрібно змінити | Відкрий |
|---|---|
| Загальний вигляд усіх вправ | [`DESIGN.md`](../DESIGN.md), потім спільні стилі нижче. |
| Логіку всього уроку | [`LESSON_FLOW.md`](../LESSON_FLOW.md). |
| Логіку або вигляд однієї вправи | Відповідний файл у [`docs/tasks/`](tasks/README.md), потім розмітку уроку. |
| Тему, текст або відповіді конкретного дня | HTML і дані відповідного уроку. |
| Поведінку кнопок, перевірку чи збереження | JavaScript відповідного тренажера. |
| Автоматичні перевірки | `scripts/` та `daily_task_app/*check*.mjs`. |

## Застосунок програми

- `index.html` — каркас сторінки програми.
- `data.js` — назви та короткі описи днів.
- `progress.js` — знімок станів і оцінок, які показує публічна програма.
- `app.js` — картки днів, відкриття уроків і навігація.
- `styles.css` — спільний вигляд програми.

## Тренажери

- `daily_task_app/index.html` і `daily_task_app/app.js` — тренажер дня 14.
- `daily_task_app/styles.css` — його стилі й адаптивне компонування.
- `daily_task_app/day30/index.html`, `app.js`, `checker.js`, `today.js`, `styles.css` — окрема версія тренажера дня 30.
- `daily_task_app/archive/` — матеріали минулих уроків, відкриті для читання.

У поточному прототипі тексти й розмітка тренажерів частково записані безпосередньо в HTML. Тому Markdown-файли з правилами пояснюють, **яким має бути результат**, але самі по собі інтерфейс не змінюють. Після погодження правила треба втілити в HTML, CSS або JavaScript і перевірити.

## Локальні перевірки

З кореня проєкту:

```bash
node scripts/test-program.mjs
node scripts/check-links.mjs
node daily_task_app/qa_check.mjs
node daily_task_app/test_drafts.mjs
```

Статичний сайт можна запустити командою `python3 -m http.server 8766`, потім відкрити <http://127.0.0.1:8766/>.
