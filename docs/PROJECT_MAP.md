# Як улаштований проєкт зараз

## GitHub і файли на комп’ютері

GitHub не є автоматичною копією комп’ютера. У GitHub потрапляють лише відстежувані файли після commit і push. Сайт English Tutor публікується з GitHub-репозиторію. Локальна робоча папка з авторськими правилами зараз окрема й не є його Git-копією.

Особистий журнал, відповіді учня та чернетки не слід автоматично публікувати. До GitHub треба перенести правила, шаблони та код збірки без персональних записів.

## Що показує сайт

- Кореневі `index.html`, `app.js`, `data.js`, `progress.js`, `styles.css` — програма, картки днів і переходи.
- Кореневий `app.js` направляє День 14 до `daily_task_app/index.html`, а День 30 — до `daily_task_app/day30/index.html`.
- `daily_task_app/index.html` — ранній окремий тренажер Дня 14 зі своїми текстами та кодом.
- `daily_task_app/day30/` — інша реалізація тренажера Дня 30. `today.js` містить матеріал уроку; `index.html` — сторінку; інші JS/CSS — взаємодію та вигляд.
- `daily_task_app/archive/` — збережені для читання матеріали минулих уроків.

Дні 14 і 30 лежать окремо, бо це різні покоління коду: День 14 створено як самостійний тренажер, а сторінку Дня 30 пізніше зібрала новіша система. Вони не використовують спільний генератор у цьому репозиторії. Згадка «Day 14 sample» була технічним описом ранньої демоверсії, а не частиною задуму курсу.

## Де насправді зберігається логіка нових задач

У локальній робочій папці є справжній ланцюжок створення уроку:

```text
lesson_factory/contract.json       порядок восьми задач і спільні обмеження
lesson_factory/tasks/<id>.json     логіка, правила та інструкція конкретної задачі
lesson_factory/current.json        матеріал поточного дня
lesson_factory/templates/<id>.html структура екрана задачі
scripts/lesson.mjs                 збирає шаблони й матеріал у HTML та today.js
daily_task_app/styles.css          вигляд зібраного тренажера
```

Наприклад, «Вибір фраз» має контракт у `lesson_factory/tasks/phrase_selection.json` і розмітку в `lesson_factory/templates/phrase_selection.html`. `scripts/lesson.mjs build` читає ці файли й формує сторінку уроку. Я перевірив результат: `today.js` Дня 30 збігається з локальною збіркою, але HTML містить ручні зміни, а опубліковані `app.js` і CSS не збігаються з актуальними локальними файлами. Тобто навіть сторінка Дня 30 зараз не відтворюється з опублікованих джерел один в один. Збирач і його джерела відсутні в GitHub, тому його неможливо відкрити чи запустити з репозиторію.

Раніше додані окремі файли `docs/tasks/*.md` були лише моїми пояснювальними копіями; збирач їх не читав. Я прибрав їх, щоб не створювати друге місце для тих самих правил. Короткий огляд у `LESSON_FLOW.md` — лише карта, не джерело збірки.

## Цільовий ланцюжок

```text
lesson_factory/contract.json + tasks/*.json + templates/*.html
                         + current.json
                                  ↓
                        scripts/lesson.mjs build
                                  ↓
                  daily_task_app/current/ (зібраний сайт)
```

Загальний вигляд змінюється у спільних стилях та оболонці; структура вправи — у її шаблоні; навчальна логіка й видимі інструкції — у контракті. Зібрані сторінки не редагують вручну. Під час перенесення збирача треба відокремити перевірку персональних доказів від публічних файлів, щоб запуск не вимагав публікації журналу учня.

## Документи й зображення

`docs/case-study.md`, `docs/presentation.md`, `docs/portfolio-copy.md` та `docs/screenshots/` — матеріали для презентації, не частина застосунку й не правила уроків. Їх слід тримати окремо від основної навігації користувача.

## Перевірки

```bash
node scripts/test-program.mjs
node scripts/check-links.mjs
node daily_task_app/qa_check.mjs
node daily_task_app/test_drafts.mjs
```

Ці команди перевіряють теперішні частини публічного сайту. Поки збирач уроків не перенесений, вони не перевіряють зв’язок контрактів з опублікованими вправами.
